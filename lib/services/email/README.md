# خدمة البريد الإلكتروني

تتولى هذه الوحدة بناء رسائل البريد وإرسالها، كما توفر معاينة محلية لقوالب الرسائل قبل استخدامها.

## مكونات الخدمة

- `templates/`: قوالب الرسائل المكتوبة بـ React وملفات TSX.
- `templates/layout.tsx`: تخطيط مشترك للقوالب، يضبط لغة الرسالة واتجاهها حسب اللغة المختارة، ويحتوي على ترويسة Marketna وتذييل موحد. يستخدم مكوّن `Tailwind` من React Email لتجهيز أصناف Tailwind داخل HTML البريد.
- `templates/newsletter-confirmation-email.tsx`: رسالة تأكيد الاشتراك في النشرة البريدية، تتضمن رابط إلغاء اشتراك مشفرًا صالحًا لمدة 24 ساعة.
- `templates/newsletter-broadcast-email.tsx`: رسالة يحررها مدير المتجر وترسل منفردة للمشتركين النشطين المحددين، مع رابط إلغاء اشتراك مشفر خاص بكل مستلم.
- `mailer.ts`: ينشئ ناقل Nodemailer ويقرأ إعدادات SMTP من متغيرات البيئة.
- `send-email.ts`: يحول مكوّن React إلى HTML باستخدام `@react-email/render`، ثم يرسله عبر ناقل Nodemailer، ويعيد نتيجة من نوع `ApiResult`.

## إعداد SMTP

أضف الإعدادات التالية إلى `.env.local` محليًا، أو إلى إعدادات البيئة السرية في بيئة النشر:

| المتغير                         | الاستخدام                                                                                       |
| ------------------------------- | ----------------------------------------------------------------------------------------------- |
| `EMAIL_USER`                    | حساب SMTP المستخدم للمصادقة. مطلوب.                                                             |
| `EMAIL_PASSWORD`                | كلمة مرور SMTP أو كلمة مرور التطبيق. مطلوبة.                                                    |
| `EMAIL_FROM`                    | عنوان المرسل الظاهر في الرسالة؛ يستخدم عند الإرسال ولا يتحقق `mailer.ts` من وجوده مسبقًا.       |
| `EMAIL_HOST`                    | خادم SMTP؛ القيمة الافتراضية `smtp.gmail.com`.                                                  |
| `EMAIL_PORT`                    | منفذ SMTP؛ القيمة الافتراضية `587`.                                                             |
| `NEWSLETTER_UNSUBSCRIBE_SECRET` | سر خاص لتشفير روابط إلغاء الاشتراك والتحقق منها. مطلوب لهذه الميزة، ويجب أن لا يقل عن 32 حرفًا. |

يتحقق `mailer.ts` من وجود `EMAIL_USER` و`EMAIL_PASSWORD` عند تحميل الوحدة، ويوقف التحميل إذا كان أحدهما مفقودًا. قيمة `secure` مضبوطة حاليًا على `false`، لذلك اضبط الخادم على منفذ يدعم STARTTLS، مثل `587`. لا تضع أسرار البريد في متغيرات تبدأ بـ `NEXT_PUBLIC_`، ولا تحفظها في ملفات موثقة أو في نظام التحكم بالإصدارات.

تستخدم أماكن إنشاء روابط الرسائل أيضًا `NEXT_PUBLIC_APP_URL` لتكوين روابط تسجيل الدخول واستعادة كلمة المرور؛ وعند غيابه تستخدم `http://localhost:3000`.

اضبط `NEWSLETTER_UNSUBSCRIBE_SECRET` في `.env.local` وبيئة النشر قبل تفعيل الاشتراك. يُستخدم تشفير AES-256-GCM لحماية البريد الإلكتروني وتاريخ إصدار الرابط، ولا يحتوي الرابط على البريد كنص ظاهر. تنتهي صلاحية الرابط بعد 24 ساعة من إنشائه. خزّن قيمة السر نفسها في جميع نسخ التطبيق التي ترسل الرسائل وتستقبل طلبات إلغاء الاشتراك.

يمكن توليد سر عشوائي مناسب باستخدام Node.js:

```bash
node -e "console.log(require('node:crypto').randomBytes(32).toString('base64url'))"
```

## معاينة القوالب أثناء التطوير

يعرض React Email القوالب في المتصفح ويعيد تحميل المعاينة عند تعديل ملفاتها. شغّل:

```bash
npm run email
```

يفتح الأمر خادم المعاينة على المنفذ `3000` افتراضيًا؛ افتح `http://localhost:3000` في المتصفح. إذا كان خادم Next.js يستخدم المنفذ نفسه، شغّل المعاينة على منفذ آخر:

```bash
npm run email -- --port 3001
```

في هذه الحالة افتح `http://localhost:3001`. اختر القالب من واجهة المعاينة لمراجعة شكله. المعاينة لا ترسل رسالة فعلية؛ إرسال رسالة تجريبيّة يتطلب استدعاء `sendEmail` مع إعدادات SMTP صالحة.

## إنشاء قالب جديد

1. أنشئ ملفًا بامتداد `.tsx` داخل `templates/`، وصدّر مكوّن React افتراضيًا.
2. عرّف خصائص القالب في نوع أو واجهة، مثل الاسم والرابط المطلوبين لتخصيص محتوى الرسالة.
3. استخدم `templates/layout.tsx` لتوحيد الترويسة والتذييل والاتجاه.
4. أنشئ محتوى البريد بمكوّنات React Email مثل `Text` و`Link` و`Button` من `@react-email/components`.
5. أضف `locale` إلى خصائص القالب، واكتب المحتوى لكل لغة مدعومة؛ مرر اللغة إلى `EmailLayout` ليضبط `lang` والاتجاه والمحاذاة. تستخدم المعاينة لغة التطبيق الافتراضية (`en`) عند عدم تمرير اللغة، وتظل الرسائل الفعلية بلغة الصفحة التي استدعت الإجراء.
6. استخدم `className` وأصناف Tailwind داخل القالب؛ يوفّر مكوّن `Tailwind` في التخطيط تجهيزها لرسائل HTML. استخدم مكوّنات البريد بدل عناصر أو أنماط واجهة الموقع التي لا تُجهّز للبريد.
7. شغّل المعاينة، وراجع النصوص والروابط واتجاه RTL وLTR قبل ربط القالب بإجراء الإرسال.

مثال مبسط:

```tsx
import { Button, Text } from "@react-email/components"

import EmailLayout from "./layout"

interface OrderEmailProps {
  locale: "ar" | "en"
  customerName: string
  orderUrl: string
}

export default function OrderEmail({
  locale,
  customerName,
  orderUrl,
}: OrderEmailProps) {
  return (
    <EmailLayout
      locale={locale}
      title={locale === "ar" ? "تأكيد الطلب" : "Order confirmed"}
    >
      <Text>
        {locale === "ar" ? `مرحبًا ${customerName}،` : `Hello ${customerName},`}
      </Text>
      <Button href={orderUrl}>
        {locale === "ar" ? "عرض الطلب" : "View order"}
      </Button>
    </EmailLayout>
  )
}
```

تتبع القوالب الحالية هذا الأسلوب؛ راجع `templates/welcome-email.tsx` و`templates/reset-password-email.tsx` لمعرفة أمثلة بخصائص وروابط فعلية.

## إرسال قالب من إجراء خادمي

أنشئ عنصر React للقالب ومرّره إلى `sendEmail` من إجراء يعمل على الخادم، كما في إجراءات التسجيل واستعادة كلمة المرور:

```tsx
import React from "react"

import { sendEmail } from "@/lib/services/email/send-email"
import OrderEmail from "@/lib/services/email/templates/order-email"

const result = await sendEmail({
  to: customerEmail,
  subject: "تأكيد الطلب",
  reactComponent: React.createElement(OrderEmail, {
    locale,
    customerName,
    orderUrl,
  }),
})
```

مرر اللغة الحالية من واجهة العميل عبر `useLocale()` إلى إجراء الخادم، ثم إلى خصائص القالب. تطبق رسائل الترحيب واستعادة كلمة المرور وتأكيد الاشتراك هذا النمط؛ إذا لم تُمرر لغة صالحة، تستخدم الرسالة اللغة الافتراضية للتطبيق (`en`). رسائل تأكيد الحساب التي يرسلها Supabase Auth تُدار من قوالب البريد في لوحة Supabase، وهي منفصلة عن هذه القوالب.

يستخدم الإرسال الجماعي في لوحة التحكم دفعات لا تتجاوز 50 مشتركًا لكل طلب. عند تعذر إرسال بعض الرسائل، تعرض اللوحة عدد الرسائل المرسلة والفاشلة وتتيح إعادة محاولة المستلمين الفاشلين فقط.

تعيد `sendEmail` إحدى النتيجتين:

- `{ success: true, data: { messageId } }` عند الإرسال.
- `{ success: false, error }` عند نقص الحقول أو فشل الإرسال.

تحقق من `result.success` عند استدعاء الدالة؛ أخطاء النقل التي تلتقطها `sendEmail` تُعاد كقيمة فشل ولا يلزم أن تُرمى كاستثناء. وقد تُرجع الدالة تفاصيل الخطأ إلى سجل الخادم، لذا لا تعرضها للمستخدم مباشرة.
